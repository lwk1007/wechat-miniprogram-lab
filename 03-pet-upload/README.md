# 03 照片上传

练：**上传完整链路** —— 选图 → 压缩 → 存储 → 入库 → 列表回显。同一份页面代码，两套数据通道。

## 跑起来

### 现在就能跑（演示模式，零配置）

直接导入本目录，`config.js` 里 `envId` 留空即可。数据存本地缓存，图片转 base64 保存，重开小程序还在。
上传、删除、预览、列表回显全部可用。

### 切成云开发（真正做项目时）

1. 用**真实 AppID** 打开本目录（测试号开不了云开发）
2. 开发者工具顶部「云开发」→ 开通 → 新建环境，复制**环境 ID**
3. 打开 `config.js`，把环境 ID 填到 `envId`
4. 云开发控制台 → 数据库 → 新建集合 `pets`，权限选「**仅创建者可读写**」
5. 重新编译，`api.js` 会自动切到云通道，页面代码一个字都不用改

## 这个项目的重点：`api.js`

页面里**没有一行 `wx.cloud`**。所有数据操作都在 `api.js`：

```js
api.list()          // 读列表
api.upload(path)    // 传一张
api.remove(record)  // 删一条
```

内部按 `config.envId` 分流。看云版和本地版并排放着，会发现结构几乎一样 ——
**换数据源只换实现，不换调用方**，这就是分层的收益，也是以后接自建后端时不用重写页面的原因。

## 10 分钟讲解

| 文件 | 看什么 |
|---|---|
| `app.js` | `wx.cloud.init({ env })` 全局只调一次；没填 envId 时不初始化，走演示模式 |
| `pages/index/index.js` | `pickAndUpload()` 是完整链路，四步都有注释：chooseMedia → compressImage → uploadFile → collection.add |
| `onShow` vs `onLoad` | 读数据放 `onShow`，才能从别的页面回来时刷新 |
| `removePhoto()` | 先 `deleteFile` 再 `doc().remove()`，反了会留孤儿文件 |

## 三个硬知识

1. **`_openid` 自动写入**：客户端 `add` 的记录自带作者 openid，所以「免注册」几乎零成本。
2. **客户端单次最多查 20 条**：`limit(20)` 是上限，要更多必须分页。
3. **`get()` 是异步的**：不 `await` 就去 `setData`，是新手第一大坑。
