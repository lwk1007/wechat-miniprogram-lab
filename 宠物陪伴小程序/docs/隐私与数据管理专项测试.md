# 隐私 / 长期保存与数据管理 · 专项测试

> 对应改动需求清单第 10 条：`隐私/长期保存与数据管理`（P0 先落地）
> 版本：v1.0　编写日期：2026-11-05
> 适用小程序：宠物陪伴（AppID `wx9ab8161a49864e29`）

---

## 一、测试目标

这条需求原本写着「已实现隐私模式与长期保存模式切换、我的动态、删除宠物及全部数据」，专项测试要回答的是三个问题：

1. **承诺与行为是否一致** —— 页面上写的「最迟 24 小时删除」，代码是否真的做到了；
2. **能不能删干净** —— 用户点删除之后，数据库、云存储、本机缓存里还有没有残留；
3. **能不能看清自己的数据** —— 用户是否有途径查阅、复制自己的信息（个人信息保护法第 45 条）。

---

## 二、数据清单（先对齐口径）

测试前必须先明确「哪些数据存在哪里、留多久、怎么删」，否则用例无从判定。

| 数据 | 存储位置 | 保留策略 | 删除方式 |
|---|---|---|---|
| 宠物档案 | 云数据库 `pets` | 长期 | 删档案 / 清空全部 |
| 宠物照片文件 | 云存储 `pet/*` | 隐私模式 22h + 每小时清理；长期模式不过期 | 清理任务 / 立即删除 / 删档案 / 清空全部 |
| 照片素材记录 | 云数据库 `mediaAssets`（`purpose='pet'`） | 同上，`status` 流转 `active → replaced / cleaned` | 同上 |
| 聊天记录 | 云数据库 `messages` | 90 天 | 删档案 / 清空全部 / 到期清理 |
| 它写的信 | 云数据库 `letters` | 每人最近 20 封，12 小时最多一封 | 删档案 / 清空全部 |
| 社区动态 | 云数据库 `posts` | 长期，公开可见 | 删单条 / 清空全部 |
| 动态图片 | 云存储 `post/*` | 随动态 | 删动态 / 清空全部 |
| 评论 / 点赞 | `comments` / `likes` | 长期 | 删单条（评论）/ 清空全部 |
| 举报记录 | `reports` | 长期，状态 `pending` | 清空全部 |
| 互动统计（喂食/摸摸次数） | **仅本机** Storage `pet_moments` | 30 天滚动 | 删档案 / 清空全部 / 清除缓存 |
| 演示数据、场景偏好 | **仅本机** Storage | 长期 | 清除本机缓存 |

**关键区别（最容易测错的地方）**

- 「删除宠物及全部数据」= 只删**私密部分**（档案、照片、聊天、信、本机统计），**社区内容保留**；
- 「清空全部数据」= 连**主动公开的社区内容**一起删（动态、图片、评论、点赞、举报）。

两者语义不同，UI 文案和确认弹窗都必须说清楚，用例 G-04 / G-05 专门验这一点。

## 三、测试环境

### 3.1 演示模式（无需云环境，可立刻跑）

- `miniprogram/utils/config.js` 中 `cloudEnvId` 为空；
- 数据全部落在本机 Storage；
- 覆盖模块 K 与页面交互，**不能**验证真实文件删除、定时清理、越权，这三类必须走云模式。

### 3.2 云模式（覆盖 A~J）

1. `config.js` 填入云环境 ID；
2. 云开发控制台建 9 个集合：`users`、`pets`、`mediaAssets`、`messages`、`letters`、`posts`、`comments`、`likes`、`reports`（权限按 README 第四节）；
3. 部署云函数：`login` / `pet` / `chat` / `community` / `cleanup` / `letter` / **`account`（本轮新增）**；
4. 确认 `cleanup` 的定时触发器 `hourly-media-cleanup` 已生效（每小时整点）；
5. 准备两个微信号（A 号与 B 号），J 组越权用例必须双账号。

### 3.3 辅助手段

| 目的 | 做法 |
|---|---|
| 看素材状态 | 控制台 → 数据库 → `mediaAssets`，按 `createdAt` 倒序 |
| 看文件是否真删 | 控制台 → 存储 → 按路径 `pet/` 筛；或直接用旧 fileID 调 `wx.cloud.getTempFileURL`，应报错 |
| 强制触发清理 | 控制台 → 云函数 → `cleanup` → 云端测试，传 `{}` |
| 制造过期 | 控制台把某条 `mediaAssets.expiresAt` 改成过去时间戳，再跑 `cleanup` |
| 看本机数据 | 开发者工具 → 调试器 → Storage 面板 |

### D. 换照片与旧素材（本轮修复项，必须回归）

> **缺陷回顾**：`pet.updatePet` 换照片时把旧素材置为 `status='replaced'`，而 `cleanup` 只清理 `active / failed`，导致**每换一次照片就有一份旧文件永久留在云存储**，隐私模式「24 小时删除」在换照片路径上完全失效。修复方式：清理白名单加入 `replaced`。

| 编号 | 操作步骤 | 预期结果 | 结果 |
|---|---|---|---|
| D-01 | 隐私模式下连续换 3 次照片 | `mediaAssets` 中出现 2 条 `replaced` + 1 条 `active`，`replaced` 的 `expiresAt` 均为替换当时的时间 | |
| D-02 | 运行 `cleanup` | 2 条 `replaced` 全部变 `cleaned`，**云存储里对应文件消失**（本轮修复核心断言） | |
| D-03 | 在控制台存储面板按 `pet/` 搜索 | 只剩当前在用的 1 个文件 | |
| D-04 | 换 3 次照片后删除宠物档案 | 所有 `purpose='pet'` 素材（含 `replaced`）记录与文件全部清空 | |
