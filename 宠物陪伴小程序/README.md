# 宠物陪伴 · 数字生命纪念小程序

一款聚焦「纪念与陪伴」的微信小程序：上传宠物的老照片，本地端到端去白底让照片「复活」，与它一起生活、留下足迹日记，在回忆时间轴里串起相遇、里程碑、思念信、来信与声音；还能把思念写进时光胶囊、约定未来某天开启，为逝去的它留下一份可延续的数字记忆。

- **无需注册即可体验**：进入即用，一键领养默认宠物
- **隐私友好**：照片默认隐私模式，最迟 24 小时自动删除；心情、思念信、时光胶囊与声音只存本机
- **不冒充宠物意识**：不对用户宣称「这就是它」，只做记忆延续与情感疗愈
- **零依赖、可直接导入**：微信原生小程序 + 云开发，未配置环境时自动进入**演示模式**

## 一、快速开始（演示模式，5 分钟）

演示模式**不需要任何 AppID、云环境或密钥**，所有数据保存在本机，用于体验完整业务闭环。

1. 打开**微信开发者工具**，选择「导入项目」
2. 项目目录选择本文件夹（包含 `project.config.json` 的目录）
3. AppID 选择「测试号」（项目已内置 `touristappid`，会自动使用游客模式）
4. 点击「导入」即可运行
5. 首页点「免费体验（一键领养）」创建默认宠物，或走完整的三步创建流程

> 演示模式的一封信来自本地模板，**不是**真实 AI 生成。

## 二、切换为真实云服务

需要：已注册的微信小程序 AppID（[注册指引](https://mp.weixin.qq.com/)）。

1. **填 AppID**：打开 `project.config.json`，把 `"appid": "touristappid"` 改为你的 AppID
2. **开通云开发**：开发者工具顶部点「云开发」→ 开通（选择按量付费，有免费额度）
3. **填环境 ID**：打开 `miniprogram/utils/config.js`，把 `cloudEnvId` 填为你的环境 ID
   （云开发控制台 → 设置 → 当前环境 ID）
4. **创建数据库集合**：在云开发控制台 → 数据库，创建下方[第四节](#四数据库集合与权限配置)列出的 4 个集合，并按说明设置权限和索引
5. **部署云函数**：在开发者工具中，右键 `cloudfunctions` 下每个函数文件夹 →「上传并部署：云端安装依赖」，共 6 个：
   - `login` / `pet` / `letter` / `cleanup` / `account` / `cutout`
   - `account` 是数据管理专用（立即删照片 / 清空全部数据 / 导出我的数据），不部署会导致「我的」页的数据管理功能报错
   - `cutout` 是智能抠图专用（见下方「智能抠图部署」），不部署时复杂背景的照片会降级为「按原图用」
6. **部署定时清理**：右键 `cloudfunctions/cleanup` →「上传触发器」（每小时自动执行一次清理）
7. 重新编译小程序，横幅消失即为真实模式 ✅

### 演示模式 / 真实服务切换方法总结

| 状态 | 判定 | 数据位置 | 一封信 |
|---|---|---|---|
| 演示模式 | `config.js` 中 `cloudEnvId` 为空 | 本机 Storage | 本地模板（按真实互动数据拼装） |
| 云端-模板信 | 已配置环境，但未配模型密钥 | 云数据库 | 云函数模板信（响应中 `isDemo: true`） |
| 云端-真实模型 | 已配置环境 + 模型密钥 | 云数据库 | 真实大模型（`isDemo: false`） |

## 三、接入真实大模型

模型调用封装在 `cloudfunctions/letter/index.js` 的适配层，走 **OpenAI 兼容接口**（可替换 Provider）。

1. 开发者工具中右键 `letter` 函数 →「云端安装依赖」后，在**云开发控制台 → 云函数 → letter → 配置 → 环境变量**添加：

```
MODEL_PROVIDER = openai-compatible
MODEL_BASE_URL = https://你的服务地址/v1
MODEL_NAME     = 你的模型名
MODEL_API_KEY  = 你的密钥
```

2. 重新部署 `letter` 函数即可。**密钥只存在服务端环境变量中，不进入小程序代码和仓库。**
3. 更换 Provider：只需修改 `letter/index.js` 中的 `generateWithModel`，其余代码不变。
4. 没配密钥时「一封信」会降级成按真实互动数据拼的模板信，功能仍然可用。

## 三·五、智能抠图部署（cutout，可选）

`cutout` 云函数用 IS-Net（`isnet-general-use.onnx`）做语义分割，把宠物主体从任意背景（草地、沙发等）里抠出来，与本地「去白底」互补。不部署不影响其它功能，只是复杂背景的照片会按原图用。

1. 把模型 `isnet-general-use.onnx`（约 178MB，fp32；或用 fp16 版约 86MB）上传到**云存储**，记下它的 fileID。
2. 在**云开发控制台 → 云函数 → cutout → 配置 → 环境变量**添加：`CUTOUT_MODEL_FILE_ID = <模型的 fileID>`。
3. 右键 `cutout` →「上传并部署：云端安装依赖」（依赖 `onnxruntime-node` + `jimp`，体积较大）。
4. 把 `cutout` 的**超时调到 60s、内存调到 1024MB**（冷启动 + CPU 推理 1024×1024 需数秒到十几秒）。
5. 抠图结果由 `pet` 云函数纳入 `mediaAssets` 生命周期，隐私模式下随 24h 清理任务一并删除，不改变隐私立场。

## 四、数据库集合与权限配置

在云开发控制台创建以下集合（权限统一设为「仅创建者可读写」，客户端不直连数据库）：

| 集合 | 主要字段 | 说明 |
|---|---|---|
| `users` | `_openid`, `nickname`, `createdAt` | 用户身份 |
| `pets` | `_openid`, `name`, `personality`(loyal/lively/foodie/friendly), `type`(cat/dog/other), `ownerName`, `sinceDate`, `storageMode`(private/persistent), `photo`(fileID), `assetId`, `createdAt` | 宠物档案，一人一宠 |
| `mediaAssets` | `_openid`, `fileID`, `purpose`(pet), `storageMode`, `expiresAt`, `status`(active/cleaned/failed/replaced), `retryCount` | 素材生命周期管理 |
| `letters` | `_openid`, `petId`, `petName`, `ownerTitle`, `content`, `isDemo`, `stats`, `createdAt` | 「一封信」AI 总结结果，每人只留最近 20 封 |

**建议索引**：`mediaAssets.expiresAt`（清理任务查询）。

**安全设计**：所有写操作经云函数执行，服务端统一从 `cloud.getWXContext()` 获取身份，不信任客户端传入的用户 ID；私有档案仅本人可读写；删除档案时同步清理素材与信。

## 六、数据保留规则（重要）

1. **隐私模式（默认）**：宠物照片及衍生素材最迟上传（或切回隐私模式）后 **24 小时内**删除。实现：有效期设 22 小时 + 每小时清理任务（含重试缓冲，保证实际保留 < 24h）。过期后使用通用形象，可重新上传，也可在「我的」里立即删除。
2. **长期保存模式（主动选择）**：宠物照片与形象持续保存、仅用于陪伴空间展示；可随时切回隐私模式并发起删除。
3. **换照片**：旧素材标记为 `replaced` 并进入清理队列，隐私模式下随下一轮清理删除。

另外：信只保留最近 **20 封**（每 12 小时最多一封），由生成逻辑控制；**心情日志、思念信、时光胶囊与声音只存本机**（`mood-log.js` / `tribute.js` / `time-capsule.js` / `voice-memory.js`），不进云端、不随档案上传，删除宠物时一并清除。

**删除的边界**

| 操作 | 删除范围 | 保留 |
|---|---|---|
| 删除宠物及全部数据 | 档案、照片、信、本机互动统计、心情、思念信、时光胶囊、声音 | 无 |
| 清空全部数据 | 上述全部 | 无（`users` 仅保留身份记录） |

**查阅与导出**：「我的 → 数据管理 → 查看并导出我的数据」汇总档案、信与素材记录，可整份复制保存。

**共享模块**：`miniprogram/utils/title.js` 会被复制到 `cloudfunctions/letter/title.js`、`cloudfunctions/pet/title.js`（云函数是独立部署包，不能跨目录 require）。改完源文件执行 `node scripts/sync-shared.js`，`node scripts/sync-shared.js --check` 会校验两份是否漂移。

## 七、功能清单

**已实现（核心）**

- 免费体验 + 简短新手引导（无需注册，静默身份建立数据归属）
- 三步创建宠物：照片（本地预览/重选）→ 名字+性格（可选项可跳过）→ 保存模式确认
- **照片去底**：本地端到端去白底，让手绘稿/老照片的宠物「贴纸化」复活，不上传、不耗流量
- **智能抠图**：复杂背景（草地、沙发等）由 `cutout` 云函数做语义分割抠出主体，透明 PNG 融入陪伴场景；隐私模式同样 24h 清理
- 性格自定义：4 个底色 + 补充特质 + 口头禅/说话方式/小怪癖 + 场景反应，影响互动飘字、提溜反应和一封信的口吻
- 陪伴页：轻量场景、待机/点击动效（纯 WXSS）、摸摸/喂食/玩耍互动短句
- 桌面态：仿手机桌面，宠物自主走动，双击读信
- 自主生命：心情状态机 + 活动 + 足迹日记 + 离线补记
- **一封信**：以宠物口吻总结近期互动（真实模型 / 模板兜底，逐字可读）
- **回忆时间轴**：相遇 / 里程碑 / 足迹日记 / 来信 / 思念信 / 声音串成一条时间线，支持「往年今日」回顾
- **心情日志**：每天记录对它的思念心情，月历色块回看；心情低落时给安抚文案 + 呼吸引导
- **思念信箱**：你写给它的思念信 + 点灯仪式（蜡烛动画），历史信列表
- **时光胶囊**：写给未来的信，锁定期间内容不可见，到期解锁、首次开启记录时间
- **声音纪念**：录下想对它说的话或它的声音，挂到时间轴；只存本机，不做声音克隆
- 宠物资料管理、隐私/长期保存模式切换、删除宠物及关联数据
- 数据管理：立即删除照片、清空全部数据、查看并导出我的数据、清除本机缓存
- 微信隐私授权：相册/相机前置校验 + 隐私保护提示弹窗
- 加载中 / 空状态 / 失败 / 重试等完整状态

## 十、开发假设记录

- 使用 **JS 而非 TS**：免去 npm/构建配置，保证「导入即运行」；类型约束通过 JSDoc 注释与运行时校验弥补
- **一人一宠**：当前版简化，重复创建会替换旧档案
- 照片裁剪简化为「压缩 + 预览 + 重选」；去底在本地做，不接云端分割接口
- tabBar 使用纯文字：避免提交二进制图标资源
- 演示模式数据存本机 Storage，删除小程序即清空
- 时间格式化为相对时间（刚刚 / n 分钟前 / n 天前）
- **伦理边界**：不冒充宠物意识、不替逝者编造话语；思念信由用户自己写，声音只保留真实录音、不做声音克隆，心情与思念数据不出设备
