# 微信小程序练习场

用来放各种练手的小程序项目。一个仓库多个项目，每个子目录是一个独立的小程序，各自带 `app.json` 和 `project.config.json`。

## 都有什么

| 目录 | 项目 | 练的是什么 |
|---|---|---|
| [`01-order-demo`](./01-order-demo) | 点单（拾光咖啡） | 列表渲染、分类筛选、跨页面状态、本地缓存、tabBar 角标 |
| [`02-pet-card`](./02-pet-card) | 宠物卡片组件 | 自定义组件、`properties` 传参、`triggerEvent` 抛事件 |
| [`03-pet-upload`](./03-pet-upload) | 照片上传 | 选图 → 压缩 → 存储 → 入库 → 列表回显 |
| [`04-pet-animate`](./04-pet-animate) | 宠物动效 | CSS `@keyframes` 循环动画，只用 `transform` |
| [`05-pet-chat`](./05-pet-chat) | 宠物口吻对话 | 模板化对话、情绪状态机、`scroll-into-view` |
| [`06-pet-feed`](./06-pet-feed) | 宠物社群 Feed | 发帖、九宫格、点赞原子自增、分页加载 |
| [`07-cleanup`](./07-cleanup) | 照片定时清理 | 过期扫描、批量删除、云函数 + 定时触发器 |

`02`~`07` 是「宠物陪伴小程序」的学习路径，配套文档见 [`docs/学习路线-宠物陪伴小程序.md`](./docs/学习路线-宠物陪伴小程序.md)。

## 现在就能跑，不用配任何环境

`03` / `06` / `07` 都做了**双数据源**：

| 模式 | 触发条件 | 数据存哪 |
|---|---|---|
| 演示模式 | `config.js` 里 `envId` 为空（**默认**） | 本地缓存，图片转 base64 保存 |
| 云开发模式 | `envId` 填了值 | 云存储 + 云数据库 |

也就是说：**现在全部 6 个练习导入就能点，不需要真实 AppID、不需要云开发环境**。
等真正开始做小程序时，只要在 `config.js` 填一行 `envId`，代码自动切到云端，页面一行都不用改 —— 这也是把数据访问收进 `api.js` 的意义。

> 云开发模式需要**真实 AppID**（项目里的 AppID 只是练习用的）和云开发环境。真实项目再配，练习阶段不用管。

## 建议的练习顺序

从「纯前端」走到「有数据」，每一步都能立刻看到效果：

| 顺序 | 项目 | 花多久 | 练完你应该能说清 |
|---|---|---|---|
| 1 | `02-pet-card` | 30 分钟 | 组件怎么收参数、怎么把点击事件抛给父页面 |
| 2 | `04-pet-animate` | 1 小时 | 为什么动效只能用 `transform`，用 `setData` 改样式为什么会卡 |
| 3 | `05-pet-chat` | 1.5 小时 | 状态机怎么驱动文案，怎么让列表停在底部 |
| 4 | `03-pet-upload` | 2 小时 | 图片为什么要压两次、`api.js` 这层为什么值得存在 |
| 5 | `06-pet-feed` | 3 小时 | 分页怎么算、点赞为什么用 `command.inc` 而不是读改写 |
| 6 | `07-cleanup` | 1.5 小时 | 扫描-删除的顺序、Cron 为什么是 7 段 |

每个项目目录里的 `README.md` 都有实现讲解和自测题，建议**先跑一遍再读**，带着"为什么这么写"的问题读效率最高。


## 怎么跑起来

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版即可）
2. 首页选「导入项目」
3. **目录选具体的子目录**，比如 `wechat-miniprogram-lab\01-order-demo`，不要选仓库根目录
4. AppID 那栏点「测试号」，确定
5. 模拟器里就能直接点

## 加一个新练习

```bash
mkdir 02-xxx
```

新目录里放一套最小骨架：`app.js` / `app.json` / `app.wxss` / `project.config.json` / `sitemap.json` + `pages/`。
编号连着往下排，`01`、`02`、`03`，排序天然就是时间顺序。
最后回到这个 README，在表格里补一行。

## 一些约定

- **每个小程序目录自带 `app.json`**，开发者工具是「一个目录 = 一个项目」，所以同仓库多项目不会冲突
- **`project.private.config.json` 不进版本控制**，它跟本机绑定，提交了会让协作方冲突
- **上传密钥（`*.key`）绝不提交**，那是能替你把代码传上微信服务器的凭据
- **AppID 可以提交**，它只是身份标识；真正的秘密是微信后台的 AppSecret，永远只放后端
