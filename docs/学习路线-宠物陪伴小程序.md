# 宠物陪伴小程序：学习路线

按需求文档倒推：**上传宠物照片 → 生成动态宠物 → 宠物口吻对话 → 社群 Feed → 照片 24h 自动删除**。

配套练手项目在仓库 `02-pet-card` ~ `07-cleanup`，每个都能单独导入开发者工具跑起来。

---

## 技术栈结论（先给答案）

| 层 | 选型 | 为什么 |
|---|---|---|
| 前端框架 | **原生小程序**（不用 uni-app/Taro） | 只有小程序一个端，跨端框架只会增加踩坑成本 |
| 后端 | **微信云开发** | 免服务器、免备案、免运维；照片上传和定时删除都有现成能力 |
| 数据库 | 云数据库（类 MongoDB） | 无 SQL、免建表，两周项目够用 |
| 存储 | 云存储 | 照片直传，配合云函数定时清理 |
| 会话 | 本地模板文案 → 云函数调大模型 | 先保上线，再谈智能 |
| 动效 | CSS `@keyframes` + 图片 | 轻量、性能好；Lottie 作为备选 |

**两个硬前提**

1. 云开发**必须用真实 AppID**，测试号（`touristappid`）开不了云开发。个人主体注册免费。
2. 涉及上传照片，必须在 `mp.weixin.qq.com` 后台填写《用户隐私保护指引》，选「相册/摄像头」用途，否则审核必驳。

## M1 小程序基础巩固（0.5 天）

已有 `01-order-demo` 的话，这节只需补齐两点。

| 知识点 | 要掌握到什么程度 |
|---|---|
| WXML / WXSS / JS | 会写列表 `wx:for`、条件 `wx:if`、事件 `bindtap` |
| `setData` | 明白**没有 DOM**，改界面只能改 `data` 再 `setData` |
| 生命周期 | `onLoad` 只跑一次、`onShow` 每次可见都跑（刷新数据放这里） |
| 路由 | `navigateTo`（带返回）/ `redirectTo` / `switchTab`（只能跳 tabBar 页） |
| 自定义组件 | `properties` 接参、`triggerEvent` 抛事件、`Component()` 注册 |

**验收**：能不看教程，给 `01-order-demo` 加一个新页面并从列表跳过去传参。

**练手**：`02-pet-card` — 宠物卡片组件（头像 + 名字 + 陪伴天数 + 心情），点击冒泡到页面。
> 关键看 `components/pet-card/index.js` 的 `properties` 和 `triggerEvent`；`pages/index/index.wxml` 里父子传参那一行是关键点。

官方文档：<https://developers.weixin.qq.com/miniprogram/dev/framework/>

## M2 云开发入门（1.5 天，**最关键**）

这节不通，后面全是空转。

> **练习阶段可以先不开通**：`03` / `06` / `07` 都做了演示模式，`config.js` 里 `envId` 留空就用本地缓存把全部交互跑通，不需要真实 AppID。
> 但**云开发的 API 语义要读懂**（下面 5 个方法）—— 真正做小程序拿到 AppID 后，填一行 `envId` 就切换到云端，页面代码不用改。
> 现在练习的重点是「交互怎么实现」，等有真实 AppID 时再练「数据怎么上云」。

### 开通顺序

1. 开发者工具 → 云开发 → 开通 → 建环境（记下**环境 ID**，形如 `pet-app-3g1xxxx`）
2. `app.js` 里 `wx.cloud.init({ env: '你的环境ID' })`
3. 云开发控制台建集合（相当于表）：`pets`、`posts`
4. 集合权限：`pets` 选「仅创建者可读写」，`posts` 选「所有用户可读，仅创建者可写」

### 必须搞懂的 5 个 API

```js
const db = wx.cloud.database()

// 1. 增
db.collection('pets').add({ data: { name: '豆豆', createdAt: Date.now() } })

// 2. 查（分页靠 limit + skip）
db.collection('pets').orderBy('createdAt', 'desc').skip(0).limit(10).get()

// 3. 改
db.collection('pets').doc(id).update({ data: { name: '新名字' } })

// 4. 删
db.collection('pets').doc(id).remove()

// 5. 上传文件（关键：photo 是本地临时路径）
wx.cloud.uploadFile({ cloudPath: `pets/${Date.now()}.jpg`, filePath: photo })
```

### 三条容易踩的坑

- **`_openid` 自动带**：客户端写入的每条记录都有 `_openid`，所以「免注册」几乎零成本 —— 直接用 `_openid` 当用户 ID。
- **一次最多查 20 条**：客户端默认 `limit` 20、上限 20（云函数里可以 100）。分页必须自己写。
- **`get()` 是异步的**：拿不到结果就去 `setData`，是新手最常见的 bug。全部用 `await`。

**验收**：从零建集合 → 上传一张图 → 写入记录 → 页面读出来渲染。

**练手**：`03-pet-upload` — 选照片、压缩、上传、入库、列表展示（这是正式项目里「上传宠物照片」那一环）。
> **练习阶段**：`envId` 留空，直接跑演示模式，先把「选图 → 压缩 → 存储 → 入库 → 回显」这条链路点通。
> **真做项目时**：填 `envId` + 换真实 AppID，否则会报 `cloud init error`。
>
> 重点看 `03-pet-upload/api.js`：它把「上传」这件事的两套实现放在一起对比 ——
> 云版三行（`compressImage` → `uploadFile` → `add`），本地版三行（`compressImage` → 转 base64 → 存缓存）。
> 页面调的是同一个 `api.upload(path)`，完全不知道背后是谁。这就是分层最实际的收益。

官方文档：<https://developers.weixin.qq.com/miniprogram/dev/wxcloud/basis/getting-started.html>

## M3 图片处理与轻动效（1 天）

### 图片

| 要点 | 做法 |
|---|---|
| 选图 | `wx.chooseMedia({ mediaType: ['image'], sizeType: ['compressed'] })` |
| 压缩 | `wx.compressImage({ src, quality: 60 })` —— 上传前必压，云存储按量计费 |
| 剪裁成圆形 | 用 WXSS `border-radius: 50%` + `overflow: hidden`，不需要 Canvas |
| 抠图（进阶） | 可选，不要自己写；用现成抠图 API，两周项目建议放弃 |

### 动效

| 效果 | 实现 |
|---|---|
| 呼吸（缩放） | `@keyframes breath { 0%,100%{transform:scale(1)} 50%{transform:scale(1.05)} }` |
| 跳动 | `translateY` + `cubic-bezier`，配上落地阴影更真实 |
| 眨眼 | 两层图片叠，上层做 `scaleY` 快速压缩 |
| 点击反馈 | `:active` 或 JS 切 class，`transition: 0.15s` |

**明确不做**：3D 场景、骨骼动画、实时渲染。需求文档里也列了规避项 —— 两周做不完，且用户要的是「情感投射」不是「技术炫技」。

**验收**：同一张宠物照片，能切 3 种循环动效，且动画不掉帧（低端机 `transform` 优先，别动 `width/height`）。

**练手**：`04-pet-animate` — 换照片 + 切换呼吸/跳动/摇头，附「为什么用 transform」的注释。

官方文档：<https://developers.weixin.qq.com/miniprogram/dev/api/media/image/wx.compressImage.html>

## M4 宠物口吻对话（1 天）

### 先做模板，别急着接大模型

理由：模板文案**零延迟、零成本、可控**，冷启动体验反而更好；大模型需要额外配 API Key、走云函数、还要考虑内容安全审核。

| 层 | 做法 |
|---|---|
| 文案池 | `utils/replies.js` 按情绪分组：`happy / miss / hungry / sleepy`，每类 6~8 条 |
| 状态机 | 记录 `mood` + `lastTopic`，避免连着两句一样 |
| 触发逻辑 | 关键词命中（「吃」→ 食物话题）+ 随机兜底 |
| 消息列表 | `scroll-view` + `scroll-into-view` 定位到最后一条 |
| 输入框 | `adjust-position` + `cursor-spacing`，否则键盘会挡住输入框 |

进阶（可选，别放第一阶段）：云函数 `chat` 里调大模型，**API Key 只放云函数环境变量**，绝不能出现在小程序代码里。

**验收**：能和「宠物」来回聊 5 轮，文案不重复，键盘不遮输入框。

**练手**：`05-pet-chat` — 纯本地模板对话，改 `replies.js` 就能换人设。

## M5 社群 Feed（1.5 天）

### 数据结构（照抄即可）

```js
// 集合 posts
{
  _openid: '自动写入',      // 作者
  content: '今天带豆豆去公园',
  images: ['cloud://...'],  // 云存储 fileID 数组
  likeCount: 0,
  likedBy: [],              // 谁点过，防重复点赞
  createdAt: 1730000000000
}
```

### 四个关键点

1. **分页**：`skip(page * 10).limit(10)`；触底用 `onReachBottom`，别用 `scroll-view` 套整页。
2. **下拦刷新**：`app.json` 页面 `enablePullDownRefresh: true`，`onPullDownRefresh` 里重置页码再 `stopPullDownRefresh`。
3. **点赞原子自增**：`db.command.inc(1)`，不要先读再写（并发会丢数据）。
4. **九宫格**：1 张走大图、2~4 张两列、5~9 张三列 —— 用 `wx:if` 分三种布局，别硬套 grid。

**验收**：A 手机发一条带图动态，B 手机能看到并点赞，点赞数实时变。

**练手**：`06-pet-feed` — 发帖、九宫格、点赞、分页加载。

## M6 隐私、自动清理与上线（1 天）

### 照片 24 小时自动删除（核心承诺，必须真做）

```
云函数 cleanup-photos
  ├─ 查 pets 集合中 createdAt < now - 24h 的记录
  ├─ 对每条记录调 cloud.deleteFile({ fileList: [fileID] })
  ├─ 删除集合记录
  └─ config.json 里配 timer 触发器：每天 3:00 执行
```

触发器配置（`cloudfunctions/cleanup-photos/config.json`）：

```json
{
  "triggers": [{ "name": "dailyClean", "type": "timer", "config": "0 0 3 * * * *" }]
}
```

> Cron 是 **7 段**（秒 分 时 日 月 周 年），和 Linux 的 5 段不一样，写成 5 段会不生效。

### 合规清单

- [ ] 后台填写《用户隐私保护指引》，勾选「相册（上传图片）」
- [ ] 首次上传前弹一次隐私授权（`wx.requirePrivacyAuthorize`）
- [ ] 用户协议 / 隐私政策静态页（可直接放 `pages/privacy`，纯文字）
- [ ] 类目选择：工具类最容易过；涉及「社区/社交」需要额外资质，**这是本项目最大的审核风险点**
- [ ] 承诺文案要和代码一致：写了「24 小时删除」，就必须真有定时任务

**验收**：手动触发云函数，24 小时前的照片在云存储和数据库里都消失。

**练手**：`07-cleanup` — 云函数 + 触发器 + 页面上手动触发测试的按钮。

官方文档：
- 定时触发器 <https://developers.weixin.qq.com/miniprogram/dev/wxcloud/guide/functions/triggers.html>
- 隐私协议 <https://developers.weixin.qq.com/miniprogram/dev/framework/user-privacy/>

## 常见坑速查

| 现象 | 原因 |
|---|---|
| `cloud init error` | `envId` 没填，或用了测试号 AppID |
| `setData` 后界面不变 | 直接改了 `this.data.xxx`，没走 `setData` |
| 列表只显示 20 条 | 客户端单次查询上限 20，要分页 |
| 上传图片很慢 | 没压缩，`wx.compressImage` 先过一遍 |
| 定时触发器不跑 | Cron 写成 5 段了，要 7 段；且要先「上传触发器」 |
| 审核驳回「隐私」 | 后台没填隐私保护指引，或代码里先采集后授权 |
| 换手机后数据没了 | 数据存了 `wx.setStorage`，要迁到云数据库 |
